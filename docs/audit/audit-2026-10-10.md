# K4remote audit: changes since v0.10.0

## Executive summary
The code is broadly solid. The 39 finder findings collapse to about 25 distinct issues after de-duplication. The verifiers confirmed all of them except J, which was refuted: HamQSL fetching is tied to its own source checkbox, as FR-UI-25 specifies. No finding is high severity. None corrupts radio state or the data path. Most are display-only, test gaps or process gaps.

Real risks, in order:
1. **Parser panic kills the spot thread (A).** One malformed HamQSL body silences every spot feed, with no `catch_unwind` anywhere.
2. **Pan Mutex held during CPU rasterisation (E).** This is a regression against v0.10.0. It is untested on a Raspberry Pi, which is a target platform.
3. **FreeDV presence counted as "stations heard" (B).** This gives 20 m and 40 m a permanent false boost in the band colours.
4. **One bad config integer resets the whole config (N).**
5. **R6 reachability gate is a name heuristic that fails open (T).** It already misses real orphans.

Caveats on the audit method:
- Verification was batched per area: one verifier each for band, 3D and xtask/docs. It was not per finding.
- Finders read code only. Verifiers added release-mode probes for A, C, D, E, M and N.
- E's cost was measured on a Ryzen 9 3900X, not on a Pi or end to end.
- Finder severities were often inflated. The finders rated A, B, E and the xtask R6 finding "high"; the verifiers rated them medium.

## Detail by area

### Band conditions (FR-UI-25)
- **A [confirmed, medium].** bandcond.rs:196. Probe input `04 Oct 2026 1é5 GMT` panics with "not a char boundary". The caller is spot_sources.rs:382.
- **B [confirmed, medium].** freedv_source.rs:518-523 and 338, spot_sources.rs:221, and the "N stations heard" label in propagation.rs. A connected idle station keeps its band at +1.
- **N [confirmed, medium].** k4-config lib.rs:1204. The trigger is a hand edit. The same applies to any type mismatch in any field.
- **G [confirmed, low].** hamqsl.rs:154. Toggling off then on while a fetch is in flight can start a second overlapping request. It is bounded to one extra request, and only a courtesy issue for HamQSL's hourly limit.
- **I [confirmed, low].** propagation.rs:46,63. The tooltip lists the ticked networks, not the contributing ones. The PSK Reporter part is by design.
- **K [confirmed, low].** hamqsl.rs `current()` and main.rs:2187-2193. A stale but reachable feed is shown as "waiting for the first update".
- **M [confirmed, low].** bandcond.rs. The tap runs before the rate gate. With 11 bands at the 4096 cap, a purge pass takes 2.9 ms every 10 ms. This needs a hostile or misconfigured feed.
- **S [confirmed, low].** main.rs:2121 and 2449. Any save while the locator field is half-typed stores `""`.
- **J [refuted].** HamQSL fetch with colouring off is as specified.

### 3D spectrum and panes (FR-PAN-15, FR-UI-26)
- **E [confirmed, medium].** See the ranked table. Measured on the Ryzen:

  | Case | Time under the lock |
  |---|---|
  | Worst-case 3D rebuild, per pane per row | about 5-10 ms |
  | Full `WfRing` redraw at 2048x256 | about 16.5 ms |
  | Incremental `WfRing` update | about 0.1 ms |
  | v0.10.0 clone | 0.03 ms |

  A full redraw happens on every key change, and the centre changes every frame while tuning. A Pi will be several times slower.
- **C [confirmed, low].** view3d.rs:68. `rows_drawn` caps the row count at `floor(tilt*ih)`, but age stays pinned to depth. Past the cap, raising Depth squeezes the same rows toward the front, so the slider works backwards.
- **D [confirmed, low].** view3d.rs:176. A front row at or below the floor projects to `y=h` and is skipped. Zero pixels light, against 198 at z=0.01.
- **F [confirmed, low].** spectrum.rs:139. `WfKey` and `View3dKey` have no `rx`. Switching a single pane from A to B at equal centre and span keeps A's coloured rows until they scroll out. The `D3Cache` case rebuilds on the next row.
- **L [confirmed, low].** spectrum.rs:832 against waterfall_gpu.rs:645-653. The CPU cap uses logical pixels and the GPU cap uses physical pixels. At scale 2 the CPU path keeps half the history.
- **Click on spot plates in 3D.** This is fixed by open PR #237, so it is not counted.

### GPU and renderer (FR-UI-27)
- **H [confirmed, low].**
  - graphics.rs:124/143. In 3D, no `Shader` widget exists, so the status reads "waiting for the first frame" forever.
  - With `K4_WATERFALL=cpu` the status line says CPU while iced stays on wgpu.
  - waterfall_gpu.rs:418. `adapter_present()` uses a different instance from the one iced uses. This one is pre-existing and can leave the waterfall blank, for example when `WGPU_BACKEND` names an unavailable backend. It is the most serious of the three, since it is functional rather than a mislabel.
- **S2 [confirmed, low].** main.rs:2061/2077. The needle `.on_release(Message::GraphicsSave)` occurs twice, so the test passes if either slider's save is dropped.

### Test gaps
- **O/P [confirmed, low].** hamqsl.rs tests do not cover an Ok but malformed body. No test carries a forecast through the worker. A's panic sits on this untested path.
- **Q [confirmed, low].** `draw_3d` and `D3Cache` have no test.
- **R [confirmed, low].** `apply_at_start` is covered only by a source-string check. Its ordering invariant, setting `ICED_BACKEND` before the adapter probe, is unprotected.

### xtask gates
- **T [confirmed, medium].** On main a53e5a1, these escape:
  - `poll_cat` (k4-transport lib.rs:239) is called only from tests, hidden by the trait default of the same name.
  - `luminance` (k4-spot style.rs:55) is called only from `contrast`, which is baselined.
  - `HamqslSource::busy` and `interval_secs` are used only in tests.
  - `attempts()` on telnet, polled, freedv_source and mqtt_source is never called from production.
- **U [confirmed, low, latent].** regions.rs finds only the literal `#[cfg(test)]`. Generic items are cut at the first comma, and out-of-line test modules are scanned as production. Nothing on main triggers it.
- **V [confirmed, low].** R7 inherits R6's misses and recognises backtick citations only. The FR-SPOT-11 example is a measuring instrument that would plainly be exempted, so it is a design limit rather than a #229-style escape.
- **W [confirmed, low].** `.githooks` do not run `cargo run -p xtask`. CI does run it, on every matrix leg. `main` is unprotected, and the ruleset (id 18141903) has enforcement disabled.
- **X [confirmed, low, latent].** `pub_fn_name` parses one line at a time, so `#[inline] pub fn`, a split `pub`, and macro-generated functions are never candidates. Nothing on main triggers it.

### Docs drift (Y) [confirmed, low]
- FR-PAN-15 says "back-to-front" but the code draws newest first with a floating horizon.
- CHANGELOG.md:37 says "29" against a baseline of 28.
- The frontmatter of the R6 baseline and R7 exemptions was not bumped after 951f165.
- README.md:113 omits the CatServer, Propagation and Graphics tabs.
- The `set_activity_tap` doc comment has landed on `set_window` in telnet.rs, mqtt_source.rs and freedv_source.rs.
- The GPU status inaccuracy is H(1).

## Classes and standing checks
| Class | Members | Standing check |
|---|---|---|
| R6/R7 name-heuristic blind spots | T, U, V, X | Replace the heuristic with real reachability. Otherwise add a self-test fixture set containing a shadowed name, an orphan chain, an attribute-prefixed `pub fn` and an out-of-line cfg(test) module. Each must be flagged, so a regression in the gate fails the build. |
| Canvas state not keyed by receiver | F, L | Build cache keys from one `KeyParts` struct that includes `rx` and the pixel unit. Add a test that switches A to B at equal centre and span and asserts a full redraw. |
| Network input parsing | A, K | Fuzz or property-test every feed parser with non-ASCII, truncated and oversized input. Wrap each source poll in `catch_unwind` with restart. Clippy `string_slice` flags direct `&str[..n]` slicing. |
| Untested production glue | O/P, Q, R, S2 | Prefer behavioural tests that call the production entry point. Count source-string needles exactly. Run mutation testing on glue modules. |
| Lock held across heavy compute | E | Add a lock-hold-time assertion or tripwire counter. Make "clone under lock, compute outside" the rule for shared state. |
| Config robustness | N, S | Add a test that parses a real file containing out-of-range values and asserts the rest of the config survives. Never overwrite a file after a failed parse. |
| Status and label honesty | H, I, K, B | Derive the status text from the observed event, not from the setting. Add a test per state, including 3D and `K4_WATERFALL=cpu`. |
| Process and gate wiring | W | Enable branch protection with required checks. Run xtask in pre-push. Add a CI step that diffs `coverage.generated.md`. |

G and M are bounded and low. No single-owner defect was found in the CAT or audio paths.
